# Автоматическая публикация событий — MVP

Статус: решения согласованы, готово к реализации.

## Назначение

Локальный ежедневный скрипт читает афишу Sava Centar, отбирает события через процесс OpenCode и публикует короткие русские сообщения в Telegram-канале.

## Границы

Один источник и один канал. Обновления, отмены, повторный анализ, изображения, дополнительные источники и внешние поиски не входят в MVP. Основной поток — один скрипт и локальный журнал; отдельные сервисы и очереди не требуются.

## Передача в реализацию

Уточнение MVP при реализации (согласовано с пользователем): журнал — один JSON-файл
на ID, созданный до обработки; любой существующий файл исключает повтор. SQLite
не используется. Блокировка параллельных запусков исключена из scope: предполагается
один экземпляр. stdout/stderr сохраняются в `~/.local/state/events/publish.log`;
строки содержат время, ID и действие/ошибку, без секретов и ротации. Это уточнение
заменяет прежнее требование эксклюзивного захвата в решении о надёжности.

Открытых продуктовых решений нет. При реализации остаётся написать скрипт, выполнить проверки из решения о надёжности и настроить локальный запуск с каналом пользователя. Единственная выполненная проба AI подтверждает успешный путь; она не заменяет эти проверки. Код приложения и реальная публикация в рамках планирования не выполнялись.
