# Автоматическая публикация событий — спецификация MVP

Labels: wayfinder:map
Status: resolved

## Destination

Согласованная спецификация MVP: ежедневный запуск на компьютере пользователя обнаруживает события Sava Centar, отбирает и описывает их через OpenCode, запускаемый процессом, и автоматически публикует в Telegram-канале. Карта завершена, когда для реализации не осталось открытых решений.

Результат: [Спецификация MVP](spec.md).

## Notes

- Планирование, без реализации и реальной отправки сообщений.
- Первый источник: https://savacentar.rs/en/events-in-the-blue-hall/ .
- Запуск раз в день на компьютере пользователя; параметры зафиксированы в решении о надёжности.
- AI-анализ через OpenCode, запускаемый процессом.
- Согласованный фильтр: концерты с вокалом на русском, английском, французском, немецком или испанском; инструментальные концерты, опера и балет независимо от языка.
- Первый запуск публикует все предстоящие события, прошедшие фильтр.
- Без подтверждения. При сомнении в соответствии фильтру либо отсутствии названия, даты или места — пропуск с причиной в локальном отчёте.
- Один короткий русский текстовый пост на событие: название, место, дата, время при наличии, ссылка на билеты или страницу события. Без картинки и выдуманных данных.
- Навыки: wayfinder; grilling и domain-modeling для разговорных решений; research для исследований; opencode для AI-процесса; ponytail для минимального решения.
- Трекер: docs/agents/issue-tracker.md. Type задаёт тип; Blocked by задаёт зависимости; Status: claimed — захват; Answer — ответ. Только метки wayfinder.
- План сессии: [x] согласовать границы; [x] создать карту и вопросы; [x] связать зависимости; [x] запустить исследования; [x] записать результаты исследований.

## Decisions so far

- [Какие данные и признаки отбора доступны в афише Sava Centar?](issues/01-source-research.md): HTML пригоден для MVP; язык вокала часто неизвестен, даты и жанры требуют проверки.
- [Как запускать OpenCode процессом для ежедневного AI-анализа?](issues/02-opencode-research.md): CLI поддерживает неинтерактивный запуск; контракт результата требует отдельной пробы.
- [Какие доказательства нужны для отбора события и подготовки поста?](issues/03-filter-contract.md): допускаются уверенные выводы по репертуару без внешнего поиска; неопределённость и конфликт дат ведут к пропуску.
- [Какую модель и параметры запуска использовать для AI-процесса?](issues/06-process-options.md): GPT-6.1 Sol, одно событие на вызов, standalone без инструментов, лимит 120 секунд без повторов в том же запуске; проба разрешена.
- [Проверка контракта процесса OpenCode](issues/05-process-check.md): одиночная проба Sol вернула валидный JSON за 4,37 секунды; ошибки и отмена не проверены и учтены в вопросе о надёжности.
- [Как ежедневный запуск избегает повторов и восстанавливается после сбоев?](issues/04-publication-reliability.md): одна попытка на ID без повторного анализа; локальный журнал, последовательная отправка и ежедневный launchd; заданы критерии приёмки.

## Not yet specified

Нет. Критерии приёмки записаны в решении о надёжности, спецификация ссылается на согласованные решения.

## Out of scope

- Обновления дат, отмены и редактирование опубликованных сообщений.
- Подключение других источников в MVP.
- Изображения, ручное подтверждение публикаций.
- Повторный анализ, автоматические повторы после ошибок, объединение разных записей источника в одну публикацию.
- Реализация и развёртывание скрипта в рамках карты.
