## Question

Основания: [данные Sava Centar](01-source-research.md), [запуск OpenCode](02-opencode-research.md), [контракт отбора](03-filter-contract.md).

Контракт ошибок и завершения процесса уточняется в [Проверке контракта процесса OpenCode](05-process-check.md).

Проба подтвердила только успешный путь. В этом решении определить поведение при nonzero exit, некорректном/неоднозначном результате и таймауте, а также проверки этих путей перед вводом публикации в эксплуатацию. Не обещать прекращение удалённого вычисления после убийства CLI; оно не проверено.

Согласовать минимальные правила идентичности события и локального учёта публикаций, повторного запуска, неоднозначного результата Telegram, частичных сбоев и пересечения запусков. Определить порядок и темп первой публикации всех подходящих событий, повторную обработку пропусков, отчёт и поведение при сне компьютера. Выбрать локальный планировщик и способ задания канала с учётом существующего Telegram-кода. Без реальных отправок и настройки расписания.

## Answer

Пользователь попросил самый простой вариант для MVP и прямо исключил повторный анализ («никогда»).

### Одна запись — одна попытка

- Единица обработки — запись Sava Centar с числовым ID источника. Разные показы с разными ID обрабатываются независимо; объединения по названию или исполнителю нет.
- Локальный журнал сохраняет ID и результат: опубликовано, пропущено, ошибка либо незавершённая попытка. Причина записывается рядом; отдельная система отчётности не нужна.
- ID сохраняется до первой попытки обработки записи. Если сохранение не удалось, обработка и отправка не начинаются. Уже известный ID всегда пропускается, независимо от прежнего результата, изменений страницы или правил фильтра.
- Повторного анализа нет, в том числе после технической ошибки. Незавершённая попытка после аварии тоже не повторяется автоматически. Это намеренное упрощение MVP: возможен пропуск события ради отсутствия повторных попыток.
- Ошибка получения общего списка завершает запуск с записью причины; необнаруженные/необработанные записи не помечаются обработанными.

### Публикация и ошибки

- Подходящие события публикуются автоматически: ближайшие по дате первыми, последовательно, с паузой три секунды между постами. Это относится и к первому запуску, без ограничения числа событий.
- Ненулевой код OpenCode, таймаут, отсутствие однозначного завершённого ответа или некорректный JSON — ошибка, без публикации данного события. В JSON проверяются ID, решение и необходимые для него поля; отсутствующие сведения не восстанавливаются догадкой.
- Неясный результат Telegram не повторяется: запись «результат неизвестен» в журнале, проверка канала вручную. Подтверждённая ошибка отправки также не вызывает повторную попытку для этой записи.
- Одновременно работает только один экземпляр скрипта. Перед работой нужен локальный эксклюзивный захват; второй экземпляр завершается без действий. Запись журнала должна выдерживать прерывание процесса, чтобы следующий запуск не забывал уже начатые попытки.
- Канал и токен задаются при настройке через существующие имена `TELEGRAM_CHAT_ID` и `TELEGRAM_BOT_TOKEN`; в спецификацию секреты не записываются.

### Расписание

- macOS `launchd`, ежедневно в 10:00 по локальному времени компьютера.
- Пропущенные во время сна срабатывания объединяются в один запуск после пробуждения, без очереди запусков за каждый пропущенный день.
- Воспроизведение пропущенных запусков после полного выключения компьютера не требуется; достаточно следующего срабатывания расписания или ручного запуска.
- Время расписания локальное для компьютера; даты событий по-прежнему оцениваются в Europe/Belgrade.

### Минимальная приёмка реализации

1. На сохранённой странице и подставном AI-ответе подходящее событие даёт один корректный запрос Telegram; повторный запуск не вызывает AI и отправку для того же ID.
2. Отклонение, ошибка AI, некорректный JSON и таймаут оставляют причину в журнале и не приводят к отправке или повторному анализу при следующем запуске.
3. Неопределённый результат отправки и прерывание после отметки ID не создают повторную отправку; второй одновременный запуск ничего не делает.
4. Первая пачка упорядочена по датам и использует паузу; расписание соответствует настройкам выше.

Ошибочные пути можно проверить подставными процессами/ответами без платных вызовов и реальных постов. Завершение удалённого вычисления после таймаута не гарантируется. Проверки выше — требования к будущей реализации, а не уже выполненные тесты.
