# Иерархия src/

## Цель

Упростить поиск кода и понимание связей между файлами. Согласованный подход:
группировать код по существующим сценариям — веб-форма и автопубликация —
с одним дополнительным уровнем каталогов. Поведение приложения сохраняется.

## Структура

```text
src/
├── main.clj
├── publish.clj
├── vendor/
│   └── telegram.clj
├── web/
│   └── views.clj
└── publication/
    ├── workflow.clj
    ├── sava_centar.clj
    ├── event_time.clj
    ├── analysis.clj
    └── ai_process.clj
```

Точки входа остаются в корне: `main.clj` запускает Cloudflare Worker,
`publish.clj` — локальную публикацию. `vendor/telegram.clj` используется обоими
сценариями; `vendor/` содержит код интеграции с внешними сервисами.
Остальные файлы размещаются рядом со своим потребителем.

| Исходный файл | Новый файл | Новый namespace |
| --- | --- | --- |
| `src/telegram.clj` | `src/vendor/telegram.clj` | `vendor.telegram` |
| `src/views.clj` | `src/web/views.clj` | `web.views` |
| `src/auto_publish.clj` | `src/publication/workflow.clj` | `publication.workflow` |
| `src/sava_centar.clj` | `src/publication/sava_centar.clj` | `publication.sava-centar` |
| `src/event_time.clj` | `src/publication/event_time.clj` | `publication.event-time` |
| `src/event_analysis.clj` | `src/publication/analysis.clj` | `publication.analysis` |
| `src/ai_process.clj` | `src/publication/ai_process.clj` | `publication.ai-process` |

## Ответственности и зависимости

- `vendor.telegram` отправляет сообщения в Telegram для обоих сценариев.
- `web.views` строит форму рекомендации события и страницу результата.
- `publication.workflow` управляет чтением источника, журналом попыток,
  оценкой, очередью и отправкой публикаций.
- `publication.sava-centar` читает список и страницу события источника.
- `publication.event-time` проверяет актуальность события по времени Белграда.
- `publication.analysis` применяет фильтр событий через AI и проверяет текст
  публикации; использует `publication.ai-process` и `publication.event-time`.
- `publication.ai-process` запускает AI и контролирует завершение процесса.

Граф вызовов сохраняется. `publish` подключает анализ через существующий
параметр `io`; `workflow` не импортирует анализ напрямую. Worker зависит
только от веб-представлений, Telegram и существующих библиотек, без Node-модулей
автопубликации. Новые переадресующие модули не вводятся.

## Объём изменений

Переместить семь файлов, обновить их namespace и все ссылки на них в
исходниках и тестах, включая код запуска дочерних процессов в тестах.
Имена функций и их параметры сохраняются. Раскладка тестов остаётся прежней.

ly2k поддерживает вложенные namespace с соответствующими путями JS.
При реализации проверить, что текущий генератор сборки обходит подкаталоги
и размещает результат согласно namespace; при необходимости минимально
скорректировать существующую конфигурацию сборки на ly2k.

Пути `.wrangler/bin/src/main.js` и `.wrangler/bin/src/publish.js` сохраняются,
как и существующие команды запуска. Правила фильтра событий, формат журнала,
обработка ошибок, таймауты и порядок внешних действий не меняются.
Журнал и отправка остаются внутри сценария, согласно предыдущему решению
в `docs/superpowers/plans/2026-10-13-src-refactoring.md`.

## Проверка

После переноса выполнить чистую сборку и `make test`, чтобы старые JS-файлы
не маскировали ошибки импортов. Проверить отсутствие ссылок на прежние
namespace в исполняемом коде и отсутствие Node-зависимостей в графе Worker.
Проверить diff на изменения поведения и ошибки форматирования.
Проверка не требует реальной отправки в Telegram или обращения к AI.

## Критерий готовности

Дерево исходников соответствует схеме, существующие тесты проходят после
чистой сборки, пути точек входа сохранены, новых зависимостей и промежуточных
интерфейсов нет. По расположению файла видно, какому сценарию он принадлежит.
